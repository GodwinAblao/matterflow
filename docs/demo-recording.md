# Two-minute demo recording script

Record the live app at https://godwinablao-matterflow.onrender.com after the latest backend and frontend changes are deployed. This is a recording guide; no video has been recorded yet.

Prepare a fresh fictional workspace and let the services finish waking before recording. Use a readable browser zoom, close unrelated tabs, and keep credentials and environment settings off screen. Stay in one tab and use its role dropdown so both roles share the same workspace.

| Time      | Show                                                                 | Suggested narration                                                                                                                                                                                             |
| --------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:15 | Landing page and Explore Demo                                        | "I am Godwin Ablao. MatterFlow is my independent Rust portfolio prototype for document readiness and legal-office operations analytics. All records are fictional."                                             |
| 0:15–0:35 | Staff register; create a matter with one required checklist item     | "Staff sees assigned matters. I can create a matter with a tailored document checklist. Each visitor has an isolated demo workspace."                                                                           |
| 0:35–0:50 | Edit the matter title and save                                       | "Metadata can be corrected without changing the reference or checklist. The backend checks permissions and record versions."                                                                                    |
| 0:50–1:10 | Record document received, switch to Reviewer, accept the requirement | "Receipt and acceptance are separate. Staff records what arrived; a reviewer approves the document. Only acceptance increases readiness progress."                                                              |
| 1:10–1:25 | Confirm readiness and show activity history                          | "Readiness is blocked until required items are accepted. Workflow actions and their activity events are saved in transactions."                                                                                 |
| 1:25–1:50 | Analytics, a category filter, record drill-down and CSV              | "Rust and SQL produce descriptive analytics. Completeness, outstanding requirements and overdue follow-ups link to the underlying records. This connects the workflow to my Business Analytics specialization." |
| 1:50–2:00 | Project information and repository link                              | "The backend uses Rust, Axum and PostgreSQL; the frontend uses React and TypeScript. The repository includes migrations, tests and metric definitions."                                                         |

For an optional longer recording, show a correction/resubmission cycle, follow-up completion, or confirmed deletion of an extra unused draft. Do not delete the main walkthrough matter. Archiving is a reviewer action and marks the matter Closed.

Watch the finished recording once. Check that text is readable, role changes are clear, and no confidential information appears. Upload it only to your chosen destination and add its real link to the application email; do not leave a placeholder video URL in the submission.
